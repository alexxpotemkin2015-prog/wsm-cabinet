# Обновление кабинета

Кабинет расположен в `finance/`. Данные пяти Google-таблиц читаются без записи в источники. Публично хранится только зашифрованный снимок. Название клиента и открытые финансовые строки не публикуются.

## Текущее состояние

Ежедневное облачное обновление подготовлено, но НЕ включено до подключения сервисного доступа Google и проверки первого запуска. Кнопка обновления в кабинете пока загружает последнюю опубликованную версию, а не запрашивает Google напрямую.

## Один раз при подключении

1. В согласованном Google Cloud-проекте включить Google Sheets API и Google Drive API. Создать отдельный сервисный аккаунт без ролей владельца проекта.
2. Предоставить его адресу роль «Читатель» только в пяти согласованных таблицах. Исходные значения и формулы не меняются.
3. Добавить в секреты репозитория `GOOGLE_SERVICE_ACCOUNT_JSON`, `FINANCE_SOURCES_JSON`, `FINANCE_ENCRYPTION_JSON`. Последние два конфигурационных файла подготовлены локально, вне публичного репозитория. Ключи и пароль не пересылать в публичные обсуждения.
4. Перенести `finance-tools/refresh-workflow.yml` в `.github/workflows/finance-refresh.yml`. Для публикации выбрать GitHub Actions в Pages; старые страницы включены в экспорт и сохраняются.
5. Создать переменную репозитория `FINANCE_REFRESH_ENABLED=true`. Запустить workflow вручную, дождаться публикации, сверить свежий снимок и вход по паролю. Только после успешной проверки считать расписание включённым.

Расписание — ежедневно в 07:00 по Москве. GitHub может задерживать старт очереди. Дата фактической загрузки всегда видна в кабинете.

## Локальное обновление из уже прочитанных источников

`node finance-tools/build-snapshot.mjs PRIVATE_SOURCE_DIR PRIVATE_SNAPSHOT_PATH`

`node finance-tools/verify-snapshot.mjs PRIVATE_SNAPSHOT_PATH`

`node finance-tools/encrypt-snapshot.mjs PRIVATE_SNAPSHOT_PATH PRIVATE_ACCESS_PATH finance/data/snapshot.enc.json`

Приватные исходники, ключи и незашифрованный снимок должны находиться вне репозитория. Пароль не хранится в браузере, в URL, в коде сайта или в публичных настройках.

## Методика

- Только 2026 год. Для ОПиУ отсутствующий период — пропуск, не ноль; значения плана не придумываются. Проценты нескольких месяцев взвешиваются по выручке.
- ДДС — ручной денежный регистр. Начало + все движения = конец; остатки не складываются между месяцами. Внутренние переводы отделены от операционных потоков.
- Зарплаты — недельный итог и его цвет. Переходящие недели распределяются по календарным месяцам пропорционально дневным значениям; итог и статус оплаты сохраняются. Ошибочные даты и суммы без имени вынесены на проверку.
- АЙК — один окончательный итог недели. Неделя, пересекающая начало 2026 года, отделяется по датированным накладным при точной сверке. Документы производителя считаются отдельно. Старые записи до 2026 не учитываются.
- ТТК — актуальный каталог, а не устаревшие счётчики сводки. Нет цены продажи по блюду — нет выдуманной маржи или процента фудкоста.

## Безопасность

Снимок сжат и зашифрован AES-256-GCM. Ключ выводится из длинного случайного пароля через PBKDF2-SHA256. Это криптографическая защита содержимого на статическом сайте, а не серверные аккаунты: всем получателям общего пароля доступен один и тот же набор данных. Смена пароля не отзывает уже скачанные и расшифрованные пользователем сведения. Для персональных ролей и немедленного отзыва сессий нужен отдельный сервер авторизации.
